## 1. herdr가 실제로 하는 일(이번에 재확인)

- **핵심은 "지속성(persistence)"이지 멀티플렉서가 아니다**: 백그라운드 서버가 에이전트 터미널을
  머신 재부팅·네트워크 끊김·사용자 접속 종료를 넘어 계속 살려둔다("노트북 뚜껑을 닫거나
  네트워크가 끊겨도 에이전트는 계속 일한다"). 아무 기기에서나 다시 붙을 수 있다.
- **에이전트 상태 추적**: working/blocked/idle을 실시간 표시 — 패인을 일일이 뒤져 멈춘 프로세스를
  찾는 수고를 없앤다.
- **에이전트 간 조율**: 소켓 API + CLI로 에이전트가 서로 패인을 나누고, 서로를 시작시키고,
  프롬프트를 보내고, "진짜 블로킹 조건"을 기다릴 수 있다(맹목적 키 입력 자동화가 아님).
- **20개 CLI 자동 인식**(Claude Code, Codex, Cursor, opencode, Grok, Copilot, Hermes 등) —
  기존 도구를 대체 안 하고 감싼다.
- 설치: `curl -fsSL https://herdr.dev/install.sh | sh`, macOS/Linux/Windows, **Apache 2.0
  오픈소스**, GitHub 3.16만 스타, YC 백킹.

## 2. 우리와의 접점 — 이번 세션에서 직접 겪은 문제와 대응

이번 세션 내내 반복된 두 가지 문제가 herdr가 정확히 겨냥하는 지점과 겹친다:

1. **"서버가 왜 또 꺼졌어" 반복 문의**: 조사 결과(BUG-51/무버그 결론) 대부분이 **세션/프리뷰
   경계에서 dev 서버 프로세스 자체가 재시작되는 것**으로 드러났다(코드 크래시 아님). 이건
   yok3x GUI 서버 얘기지만, herdr가 노리는 "재부팅·접속 종료를 넘어 프로세스를 계속 살려두는"
   문제와 근본적으로 같은 종류다.
2. **codex 백그라운드 디스패치 관찰**: 이번 세션에서 codex를 여러 번 `run_in_background`로
   띄우고 출력 파일을 폴링해서 확인하는 패턴을 계속 썼다 — herdr의 `agent start`→`agent wait
   --until idle|done|blocked`→`pane read`가 개념적으로 거의 같은 일을 한다.

**단, 중요한 구분**: 이번 세션에서 겪은 "서버가 꺼짐"은 **내가 쓰는 codex CLI 백그라운드
프로세스나 yok3x GUI 서버 얘기지, herdr가 관리하는 "에이전트 터미널"과는 다른 계층**이다.
herdr를 설치한다고 yok3x GUI 서버나 codex 서브프로세스의 생명주기가 자동으로 바뀌진 않는다
— herdr는 **터미널 세션**(사람이 `claude`/`codex` 등을 실행하는 셸) 수준에서 지속성을 주는
도구고, yok3x가 자체적으로 `subprocess.Popen`으로 띄우는 워커 프로세스는 여전히 yok3x 자신의
책임이다.

## 3. 통합 방향 재검토(TODO.md 원안의 두 후보 재평가)

TODO.md 원안은 (a) 사용자가 그냥 도구로 설치, (b) `backends.py`가 herdr 소켓 API를 선택적
백엔드 실행 경로로 지원 — 두 가지를 후보로 남겼다. 이번에 얻은 정보로 재평가:

- **(b)는 권하지 않는다.** yok3x는 이미 `backends.py`에 BUG-4/10/18/43 등 여러 세대에 걸쳐
  단단하게 다듬어진 자체 subprocess 실행 계층(stdin 데드락 방지, Windows npm .cmd 멀티라인
  잘림 방지, job object 기반 프로세스 트리 정리)이 있다. herdr는 **사람이 터미널 세션을 잃지
  않게 하는 도구**지, yok3x가 워커를 실행하는 방식을 대체할 이유가 없다 — 오히려 두 프로세스
  관리 계층이 겹치면 새로운 실패 모드(예: herdr가 관리하는 세션 안에서 yok3x가 또 자체
  job object로 자식을 관리하려다 충돌)를 만들 위험이 있다. **의존성 0 원칙과도 안 맞음**
  — herdr는 외부 바이너리 shell-out이 아니라 **상시 실행되는 별도 백그라운드 서버**라
  claude/codex CLI(요청 시에만 뜨는 프로세스)와 성격이 다르다.
- **(a)만 유효하다.** yok3x 코드는 전혀 안 건드리고, **사용자가 개인 도구로 설치해서** 여러
  `claude`/`codex` 세션(이 세션 자체를 포함해)을 터미널에서 지켜보는 용도로 쓰는 것.

## 4. 권고

**코드 변경 없음.** herdr는 yok3x 저장소에 통합할 대상이 아니라 **사용자의 개인 워크플로우
도구**로 남긴다. 사용자가 여러 codex/claude 세션을 터미널에서 동시에 보고 싶을 때(이번
세션에서 여러 codex 백그라운드 작업을 폴링했던 것처럼) 설치해서 써보는 것을 권한다 — 단
이건 사용자의 선택이고, yok3x 코드나 이 계획서가 뭔가를 만들 필요는 없다.
