상태: **검토 완료 — 신규 구현 권고 없음(진단 렌즈로만 활용)** (TODO.md V-3를 사용자 요청으로 승격)

**배경**: `docs/TODO.md` V-3(AutoResearch 실패 분류, arXiv 2608.14905)를 사용자 요청으로 계획서
단계로 승격했다. 원문(초록)을 이번에 직접 확인했다 — TODO.md 등록 당시엔 "45개 패턴 목록을
못 얻어서 원문 확인 필요"로 남겨뒀던 부분이다.

## 1. 원문에서 새로 확인한 것

- **45개 실패 패턴의 개별 목록은 초록에 없다** — 논문이 "ARFT(AutoResearch Failure Taxonomy),
  45개의 실증적 실패 패턴 프레임워크"를 만들었다고만 밝히고, 초록 수준에서는 카테고리를
  나열하지 않는다. 전체 목록을 보려면 논문 본문(표/부록)을 읽어야 한다 — **이번 검토에서도
  본문 접근은 안 함(초록 기반)**. 45개 패턴 대조는 이 계획서의 범위 밖으로 남긴다.
- **핵심 진단(원문 인용)**: "current agents lack a metacognitive loop, which entails the
  ability to check what they produced against what they found, revise when it does not hold
  up, and question whether the path they took was sound."
- **중요한 추가 사실(TODO.md 등록 당시엔 몰랐던 것)**: 이 결핍은 **"8개 하네스-모델 조합
  전체에서, 가장 강한 모델을 포함해" 공통으로 나타났고, 저자들은 이를 특정 스캐폴드가 아니라
  모델 수준의 결핍으로 위치시킨다.** 즉 프롬프트/하네스를 아무리 잘 짜도 이 논문 기준으로는
  완전히 없앨 수 있다는 근거가 없다.
- **원문이 명시적으로 밝히는 한계**: "whether orchestration-level interventions can close it
  is an open question this work does not test." **이 논문은 해결책을 제시하지 않는다** —
  진단 프레임워크(ARFT)와 벤치마크(AutoResearchEval)를 공개하는 것이 기여점이다.

**결론**: 이 논문에서 "이렇게 구현하면 된다"는 처방을 가져올 수 없다 — 애초에 논문 자체가
그런 처방을 안 준다. 대신 이 논문은 **우리 T-1 문제를 재해석하는 진단 렌즈**로서 가치가 있다.

## 2. yok3x 현황과의 대조

| 논문 개념 | yok3x 현재 구현 | 실제로 메타인지 루프인가? |
|---|---|---|
| "발견한 내용과 산출물 대조" | `anti_hallucination`(`orchestrator.py:771`)이 응답에서 과잉확신 표현(`_OVERCONFIDENCE`)을 문자열 매칭으로 찾아 `검증필요` 표시 | **아니다** — 실제 근거 대조가 아니라 표면적 문구 패턴 매칭. producer 자신이 "내가 찾은 것과 내가 만든 것"을 비교하는 로직은 없음. |
| "안 맞으면 수정" | `require_selfcheck`(`yok3x_technique`, 프롬프트 지시) | 지시일 뿐 — 실제로 producer가 자기 산출물을 검증했는지는 yok3x가 확인 안 함(self-report). |
| "택한 경로가 타당한지 의문 제기" | 없음 | 없음 — producer는 한 번 접근을 정하면 라운드 내내 그 경로를 고수(reviewer 피드백 반영은 별개). |
| **외부 검증으로 대체** | producer-reviewer 패턴(타인이 검증), `verify_cmd`(객관적 테스트) | **이게 yok3x의 실질적 답**이다 — 자기검증이 약하다는 걸 인정하고, 자기검증 대신 **독립적인 제3자(reviewer) + 객관적 검증(verify_cmd)**로 우회한다. |

## 3. 핵심 통찰 — T-1과의 연결(이번에 새로 발견)

`docs/TODO.md` T-1은 codex-critic 심판이 "명백한 결함을 원본보다 낮게 평가"하는 문제를
캘리브레이션으로 고치려 하고 있다(작업E: blind 채점으로 라벨 누출 제거, 효과 미측정).

**이 논문의 발견을 그대로 적용하면**: reviewer도 결국 모델이다. "8개 하네스-모델 조합
전체, 가장 강한 모델 포함"이 메타인지 결핍을 보였다는 게 사실이면, **reviewer(codex-critic)
자신도 "내가 채점한 게 실제로 옳은지" 스스로 재확인하는 능력이 부족할 수 있다** — 이건
producer 문제가 아니라 T-1이 다루는 "심판 신뢰도" 문제 자체와 같은 뿌리일 가능성이 있다.

**실무적 함의**: 작업E(blind 채점) 같은 **프롬프트/스캐폴드 수준의 개선만으로 T-1의 심판
신뢰도 문제가 완전히 해결될 거라 기대하면 안 된다** — 논문 저자들 자신이 "오케스트레이션
수준 개입이 이걸 닫을 수 있는지는 이 연구가 테스트하지 않은 열린 질문"이라 말한다. T-1의
캘리브레이션 결과가 나중에 "여전히 낮은 상관"으로 나오더라도, 그게 작업E가 잘못됐다는
뜻이 아니라 **애초에 모델 수준 한계일 수 있다**는 걸 미리 염두에 둬야 한다(사후 실망/과잉
대응 방지).

## 4. 권고

**이 계획서에서 새로 구현할 것은 없다.** 이유:
1. 논문 자체가 해결책을 안 준다(§1의 명시적 한계).
2. 45개 패턴 상세 대조는 본문을 안 읽어서 이번엔 못 했고, 억지로 지어내지 않는다.
3. yok3x가 이미 "자기검증 대신 외부검증"이라는, 이 결핍에 대한 합리적인 구조적 우회를
   갖고 있다(producer-reviewer, verify_cmd) — 이게 최선의 현재 대응이라고 판단한다.

**대신 두 가지를 문서로만 남긴다**:
- `docs/TODO.md` T-1에 이 계획서를 참고 링크로 추가해, T-1 결과 해석 시 "심판도 모델이라
  같은 결핍을 가질 수 있다"는 맥락을 잃지 않게 한다.
- 나중에 시간이 나서 논문 본문(45개 패턴 표)을 실제로 읽게 되면, `docs/reports/bugs/`의
  BUG-01~53 목록과 대조해 yok3x에서 실제로 재현된 패턴이 있는지 확인하는 것을 후속 작업
  후보로 남긴다(예: BUG-13 자기오염 루프는 "발견한 내용과 산출물 대조 실패"의 한 사례로
  보임 — 직관적 대응이지만 45개 공식 분류와 매칭은 안 해봄).
