# 계획 · 백엔드 계정 등록 UI (YOK-86)

- **작성**: 2026-09-06 · **상태**: 명세 완료, 구현 대기(codex 쿼터)
- **지시**: 사용자 — "이거 이렇게만 던져주고 수정하세요 하면 내가 뭔 줄 알고 수정해?
  우리 사이트상에서 백엔드의 다른 계정 등록하는 UI를 제공해줘야지"
- **이슈**: YOK-86 · 선행 [[YOK-87]](실계정 e2e 검증)

## 문제

두 번째 계정을 쓰려면 지금은 `backends.json`에 이런 걸 **손으로** 넣어야 한다:

```json
"codex-alt": {
  "type": "cli", "command": ["codex","exec","--json","--skip-git-repo-check"],
  "model_arg": ["--model","{model}"], "effort_arg": ["-c","model_reasoning_effort={effort}"],
  "parser": "codex_jsonl", "timeout_sec": 600,
  "account_of": "codex", "env": { "CODEX_HOME": "~/.codex-alt" }
}
```

`type`·`parser`·`model_arg`는 **원본 backend에서 그대로 복사되는 값**이다. 사용자가 실제로
정해야 하는 건 `이름` · `어느 계정의 복제인가` · `인증 디렉터리` 셋뿐인데, 나머지 보일러플레이트가
같이 노출돼 "뭘 고치라는 건지 모르겠다"가 된다. **UI가 없다는 것이 결함이다.**

**즉 남은 것은 GUI 한 장뿐이다.**

## 범위

### 1. 새 카드 — `#settings` 뷰, "가드 · 한도" 카드 **바로 뒤**

제목: `백엔드 계정 — 쿼터가 찬 계정 대신 자동 전환`

등록된 backend를 표로 보여준다. 원본(`account_of` 없음)은 회색, 계정 복제는 배지로 구분:

| 이름 | 계정군 | 인증 경로 | 지금 사용률 | |
|---|---|---|---|---|
| `codex` | 원본 | `~/.codex` | 7d 100% 🔴 | |
| `codex-alt` | codex 복제 | `~/.codex-alt` | 7d 12% 🟢 | 편집·삭제 |

사용률은 `/api/state`가 이미 backend별로 내려주는 값을 재사용한다(신규 조회 없음).

### 2. "계정 추가" 폼 — 입력 3개만

| 필드 | 입력 방식 | 검증 |
|---|---|---|
| 어느 backend의 다른 계정인가 | 드롭다운(`account_of` 없는 backend만) | 필수 |
| 이름 | 텍스트, 기본값 `<원본>-alt` 자동 제안 | `^[a-z0-9][a-z0-9_-]{0,31}$`, 중복 거부 |
| 인증 디렉터리 | 텍스트 + 찾아보기(`/api/pickdir` 재사용) | 기본값 `~/.codex-alt`·`~/.claude-alt` |

나머지(`type`·`command`·`parser`·`model_arg`·`effort_arg`·`timeout_sec`)는 **원본에서 복사**해
사용자에게 보이지 않는다. `env` 키도 원본에 따라 자동 결정:

- `account_of: claude` → `CLAUDE_CONFIG_DIR`
- `account_of: codex` → `CODEX_HOME`
- `account_of: gemini` → **선택 불가**(비활성 + 사유 표시). `~/.gemini` 하드코딩이라 안전한 격리 수단이
  없다(TODO 조사 결과). 홈 디렉터리를 통째로 바꾸는 우회는 부작용이 커서 제공하지 않는다.

저장 시 쿼터 추적 경로도 **같이** 기록한다 — 이걸 빠뜨리면 전환은 되는데 사용량이 원본에
합산된다(YOK-87이 지적한 함정):

- claude → `limits.<name>.projects_dir = <인증경로>/projects`
- codex → `limits.<name>.sessions_dir = <인증경로>/sessions`

### 3. 로그인은 UI가 하지 않는다 (보안 경계)

**폼은 자격증명을 절대 받지 않는다.** 경로만 받는다. 저장 후 안내 문구와 복사 버튼만 제공:

```
CODEX_HOME=~/.codex-alt codex login
```

사용자가 터미널에서 직접 로그인한다. GUI가 토큰·비밀번호를 입력받거나 대신 로그인하지 않는다.
저장 후 해당 경로에 인증 파일이 없으면 `⚠ 아직 로그인 안 됨`으로 표시하고, 있으면 `✅ 연결됨`.

### 4. 폴오버 옵션 노출 (YOK-86 원래 항목)

같은 카드 하단:

- `switch_before_degrade` — 체크박스. "모델을 낮추기 전에 여유 있는 계정으로 먼저 전환"
- `failover_min_gain` — 숫자(%p, 기본 10). "이만큼 더 여유로운 계정으로만 전환(스래싱 방지)"

### 5. 서버 — 신규 엔드포인트

`/api/config`는 **`yok3x.json` 전용**이라(`_apply_config`, guiserver.py:677) 재사용 불가.
`backends.json`을 쓰는 별도 엔드포인트가 필요하다:

- `POST /api/backends/add` — `{account_of, name, auth_dir}` → 원본 복사 + `env` + `limits.*` 기록
- `POST /api/backends/remove` — `{name}` (원본은 거부, 복제만 삭제)

기존 관례 준수: 저장 전 `.bak` 백업, `atomic_write_text`, 검증 실패 시 **저장하지 않고 사유 반환**
(조용한 폴백 금지). 워커·routing이 참조 중인 backend는 삭제 거부.
