## 핵심 구조 — 캐러셀은 **계정군마다 하나씩**

전체를 하나의 캐러셀로 묶는 게 아니다(1차 오독). **카드는 지금처럼 계정군별로 나열되고,
각 카드 안에서만 그 계정군의 계정들을 횡스크롤로 넘긴다.**

```
  claude 카드              codex 카드               gemini 카드
┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│  [ claude ]  │        │  [ codex ]   │        │  [ gemini ]  │
│    ● ○ ⊕     │        │    ● ○ ⊕     │        │     ● ⊕      │
└──────────────┘        └──────────────┘        └──────────────┘
   ↓ 오른쪽 스크롤 / 두 번째 점 클릭
┌──────────────┐
│[ claude-alt ]│
│    ○ ● ⊕     │
└──────────────┘
```

- 슬라이드 = **그 계정군의 계정들** (원본 → 복제들) + 맨 끝 `⊕ 계정 추가` 슬라이드
- 점 개수 = 그 카드의 슬라이드 수. 마지막 `⊕`는 시각적으로 구분
- **복제가 아직 없어도** `⊕` 슬라이드는 있다 → 오른쪽으로 밀면 그 계정군의 추가 폼이 나온다
  (지시 2의 "백엔드 없어도 횡스크롤하면 추가하기 버튼"이 여기에 해당)
- gemini는 `⊕` 슬라이드가 비활성 + 사유 표시(인증 디렉터리 격리 불가)

## 카드 내용은 **기존 그대로**

지시 3: "각 카드 나오는 건 기존처럼 나오게 하고". 지금 표에 있는 항목을 슬라이드 하나에 담는다 —
이름 · 계정군(원본/복제) · 인증 경로 + 연결 상태(✅/⚠) · 사용률 · 편집·삭제(복제만).
**새 정보를 발명하지 말 것.** 미로그인이면 로그인 명령 + 복사 버튼을 그 슬라이드 안에.

## 카드 순서를 사용자가 지정

지시 3: "나오는 순서는 사용자가 지정할 수 있게 하자". **계정군 카드가 나열되는 순서**를 바꾼다.

- 카드 헤더에 ↑/↓ 버튼(드래그앤드롭은 접근성·터치 문제가 커서 이번 범위 밖)
- 저장: `yok3x.json`의 `gui.backend_card_order`(문자열 배열, 계정군 이름). 기존
  `POST /api/config`에 이 키를 받는 분기 추가 — 검증(알 수 없는 이름 거부·중복 거부) 후 저장
- 목록에 없는 계정군은 뒤에 원래 순서로 붙인다(새 backend가 생겨도 안 사라지게)

## 제약

1. `renderBackendAccounts()`와 그 전용 마크업/CSS만 손댄다. 다른 카드·렌더 경로 금지
2. 네이티브 `scroll-snap` 사용. **캐러셀 JS 라이브러리 금지**(의존성 0 원칙)
3. **폴링(7초) 재렌더에 각 카드의 스크롤 위치가 튀지 않아야 한다.** 카드마다 독립적으로 보존
4. 기존 `.acct-*` 클래스·CSS 토큰을 따르고 **새 색상 토큰 금지**. 라이트/다크 both
5. 가로 스크롤이 페이지 전체로 새지 않게 각 카드 컨테이너 안에서만
6. 서버 변경은 **`gui.backend_card_order` 저장 분기 하나만**. `/api/state` 응답 형태는 유지
7. 폴오버 옵션(`switch_before_degrade`·`failover_min_gain`)은 전역 설정이라 카드 밖 하단 유지
