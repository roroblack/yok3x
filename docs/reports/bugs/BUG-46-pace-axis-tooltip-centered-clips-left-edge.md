# BUG-46 · 상한 배분 방식 +/- 아이콘 툴팁이 좁은 화면에서 좌측으로 잘림

- **상태**: 수정 완료(2026-08-13)
- **심각도**: 낮음 — 기능 자체(정책 저장)는 정상, 툴팁 텍스트 일부만 안 보이는 표시 문제.
- **영역**: `gui/index.html`의 `.pace-axis-ico[data-tip]:hover::after` CSS(설정 탭 "상한 배분
  방식" 좌측 ＋/－ 아이콘 호버 툴팁).
- **발견 경로**: 사용자가 좁은 화면(작은 뷰포트)에서 아이콘에 호버했을 때 툴팁 왼쪽이 잘려
  다 안 보인다고 신고.

## 증상

설정 탭의 "상한 배분 방식"에 있는 ＋(안 쓴 만큼)/－(초과 시) 아이콘에 마우스를 올리면 뜨는
설명 툴팁이, 화면(브라우저 창)이 좁을 때 왼쪽 부분이 화면 밖으로 넘어가 잘려서 안 보였다.

## 근본 원인

이 아이콘들의 툴팁은 이전 버그(BUG-45와 같은 세션에서, 상한 배분 UI를 언더유즈/오버유즈
2축으로 분리하면서) 추가한 것으로, 전역 `[data-tip]:hover::after` 규칙(왼쪽 정렬:
`left:0` — 트리거 요소의 왼쪽 경계에서 시작해 오른쪽으로만 펼쳐짐)을 그대로 쓰면 툴팁이
너무 길어서(문장형 설명) 강제로 여러 줄로 줄바꿈되는 문제가 먼저 있었다. 그걸 고치면서
`.pace-axis-ico[data-tip]:hover::after`에 `left:50%` + `transform:translateX(-50%)`로
**아이콘 중앙 기준 좌우 대칭 배치**로 바꿔 한 줄로 보이게 했는데, 이 아이콘들이 설정 패널의
**왼쪽 가장자리에 가깝게 위치**해 있어서, 중앙 정렬하면 툴팁의 왼쪽 절반이 화면(또는 패널)
왼쪽 경계를 넘어가 잘리는 문제가 새로 생겼다 — 뷰포트가 좁을수록 더 심하게 나타난다.

## 진단

1. 사용자 신고(스크린샷 없이 텍스트로 "좌측에 짤려서 다 안보이는 버그") 기반으로
   `.pace-axis-ico[data-tip]:hover::after`의 `left:50%`/`transform:translateX(-50%)`를
   확인 — 아이콘이 왼쪽 가장자리 근처에 있는데 중앙 정렬이면 구조적으로 왼쪽이 잘릴 수밖에
   없음을 코드만 보고 특정.

## 수정

`.pace-axis-ico[data-tip]:hover::after`의 정렬 방식을 중앙 정렬(`left:50%` +
`transform:translateX(-50%)`)에서 **왼쪽 정렬**(`left:0`, transform 제거)로 변경했다 —
전역 `[data-tip]` 규칙과 같은 방향으로 통일해, 툴팁이 아이콘 왼쪽 경계에서 시작해 오른쪽으로만
펼쳐지게 했다. 한 줄로 보이게 하는 다른 속성(`max-width:none`·`width:max-content`·
`white-space:nowrap`)은 그대로 유지했다(BUG-45 계열에서 고친 세로 줄바꿈 문제는 재발하지
않음).

## 검증

- codex에게 수정을 위임하고 diff·`python -m pytest -q` 결과를 직접 확인.
- 전체 테스트 스위트 회귀 없음.

## 교훈

- **툴팁처럼 위치가 고정된 UI 요소를 "중앙 정렬"로 고칠 때는 그 요소가 컨테이너의 어느
  가장자리에 있는지 먼저 확인해야 한다** — 화면 중앙 근처에 있는 요소라면 중앙 정렬이
  안전하지만, 가장자리에 붙어 있는 요소를 중앙 정렬하면 그 방향으로 항상 잘릴 위험이
  구조적으로 생긴다. 왼쪽 정렬(`left:0`)처럼 "그 요소를 기준으로 한쪽으로만 펼치는" 방식이
  더 안전한 기본값이다.
- 같은 세션 안에서 짧은 시간에 UI를 두 번 연속 고치면서(줄바꿈 수정 → 정렬 수정) 매번
  다른 각도의 잘림 문제가 새로 생겼다 — 작은 CSS 수정이라도 "이 요소가 화면의 어느 위치에
  있을 수 있는지"(좁은 화면·가장자리 배치 등 극단 케이스)를 한 번에 같이 점검하는 게
  왕복 수정 횟수를 줄인다.
