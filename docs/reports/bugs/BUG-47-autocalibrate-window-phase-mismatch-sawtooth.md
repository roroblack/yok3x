# BUG-47 · autocalibrate가 롤링/텀블링 창을 섞어 역산해 주 단위 톱니로 진동(수렴 실패)

- **상태**: 수정 완료 (2026-08-15)
- **심각도**: 높음(자동 캘리브레이션이 원리적으로 수렴 불가 → 사용자가 `autocalibrate=false`로 꺼둠)
- **영역**: `yok3x/limits.py` `autocalibrate_claude` / `claude_rolling_tokens`
- **선행**: [[BUG-35]](BUG-35-autocalibrate-cap-swing-unbounded.md) — 같은 증상을 **증상 쪽에서** 막은 시도

## 증상

autocalibrate가 켜져 있으면 `limit_5h_tokens`/`limit_7d_tokens`가 계속 오르내리며 참값에
정착하지 않는다. BUG-35에서 회당 ±25% 클램프를 넣은 뒤로도 "수렴하지 않고 진동한다"가 남았고,
결국 사용자가 `autocalibrate: false`로 꺼둔 상태였다.

## 근본 원인 — 분자와 분모가 서로 다른 창을 가리킨다

역산식은 `cap = tokens / (live_pct / 100)`이다. 이게 성립하려면 분자(로컬 토큰)와
분모(서버 보고 %)가 **같은 구간**을 재야 한다. 그런데:

| | 무엇을 재나 | 창 종류 |
|---|---|---|
| 분모 `live_pct` | OAuth가 보고하는 사용률 | **텀블링** — `resets_at`에 0으로 리셋 |
| 분자 `claude_rolling_tokens()` | 직전 N시간 토큰 합 | **트레일링 롤링** — 항상 `now − N` |

리셋 직후엔 트레일링 창이 **지난 창의 사용량까지 끌고 온다**. 분모는 리셋돼 작고 분자는
부풀어 있으니 파생 cap이 폭등하고, 창이 진행될수록 두 구간이 겹쳐가며 참값으로 내려온다.
즉 파생 cap은 노이즈가 아니라 **주기 7일(5h 창은 5시간)의 결정론적 톱니**다.

### 실측 (2026-08-15, 로컬 트랜스크립트 80,914 이벤트 / 48.6일)

7d 창(리셋 08-09 17:59 → 08-16 17:59) 안에서 두 집계를 같은 시점끼리 비교:

| 창 경과 | trailing-7d | since-reset | 파생 cap 오차 |
|---|---:|---:|---:|
| 0.0일 | 7,185,427,293 | 0 | **∞** |
| 0.5일 | 5,959,592,271 | 0 | **∞** |
| 1.0일 | 4,909,815,465 | 1,334,021,437 | **3.68x** |
| 2.0일 | 5,761,422,211 | 4,321,025,491 | 1.33x |
| 3.0일 | 7,405,300,015 | 7,091,458,450 | 1.04x |
| 4.0일 | 8,923,129,435 | 8,846,214,432 | 1.01x |
| 5.76일(현재) | 10,264,993,223 | 10,264,993,223 | 1.00x |

주 초반 cap을 최대 3.68배 부풀렸다가 주말로 갈수록 1.00x로 내려온다 —
**매주 같은 모양으로 반복**되므로 클램프가 있어도 값은 이 톱니를 따라 오르내릴 뿐이다.

### BUG-35의 클램프가 못 고친 이유

±25% 클램프는 **슬루 레이트 리미터이지 필터가 아니다**. 목표값이 노이즈면 감쇠 효과가 있지만,
여기서는 목표값 자체가 주기적으로 움직인다. 클램프는 점프를 램프로 바꿀 뿐이고 stored는 계속
톱니를 추종한다. BUG-35가 관측한 `246M→423M→793M`(3.2배)도 이 창 위상 불일치 배수와
정확히 같은 크기다 — 당시 "작은 %에서의 노이즈 증폭"으로 귀인한 것이 오진이었다.

부수적으로, `|derived − stored| < 25%`이면 클램프가 걸리지 않아 `stored := derived`로
**노이즈가 1:1 통과**한다. 평균화(EMA) 단계가 아예 없다.

## 수정

**1. 창 위상 정렬 (핵심).** 새 `claude_window_tokens(conf, window, resets_at, now)`가
`resets_at − 창길이` 이후 토큰만 센다. autocalibrate는 이제 트레일링 롤링을 쓰지 않는다.
`claude_rolling_tokens`는 트랜스크립트 폴백 추정용으로 그대로 남는다(용도가 다르다).

**2. 위상 불명이면 보정하지 않는다.** `resets_at`이 없거나 이미 지난(stale) 값이면
미정렬 역산으로 넘어가지 않고 건너뛴다 — 틀린 cap보다 무보정이 낫다.

**3. 저관측 거부.** `live_pct`는 정수로 양자화돼 온다(예: `5.0`). 상대 불확실도는 `0.5/pct`이고
그게 그대로 파생 cap 오차가 된다 — 5%면 ±10%로 기존 ±5% 데드밴드보다 커서 폴마다 새 값이
저장되며 진동한다. 양자화 오차가 `calib_max_quant_err`(기본 0.05)를 넘으면 건너뛴다.
실질적으로 **`live_pct ≥ 10`부터 보정**한다.

BUG-35의 ±25% 클램프와 ±5% 데드밴드는 2차 방어선으로 유지했다.

## 검증

- 신규 `test_claude_window_tokens_counts_only_since_window_start`: cutoff가 `now−7d`가 아니라
  `resets_at−7d`임을 확인.
- 신규 `test_autocalibrate_claude_ignores_pre_reset_tokens`: 리셋 1일차 상황에서 창 밖 토큰
  102.4억이 있어도 창 안 13.34억만 써서 cap을 낸다(트레일링이면 7.7배 부풀었을 값).
- 신규 `test_autocalibrate_claude_skips_without_reset_phase`: `resets_at` 없음/과거 둘 다 스킵,
  트랜스크립트를 아예 읽지 않음.
- 신규 `test_autocalibrate_claude_skips_quantization_noise`: 5%는 거부, 20%는 통과.
- 기존 8개 autocalibrate 테스트는 위상 있는 창으로 갱신해 유지(클램프·데드밴드·비현실 거부·
  rate-limit·per-model 창 제외·off 동작 전부 불변).
- `pytest tests/ -q` → **465 passed, 1 skipped**.

## 남은 사항 (이번 수정 범위 밖)

- **평균화(EMA)가 없다.** 위상 정렬로 계통 오차는 사라졌지만, 데드밴드를 넘는 잔여 노이즈는
  여전히 1:1로 stored에 반영된다. 관측이 쌓이면 EMA로 바꾸는 것이 정석이다.
- **`_CLAUDE_CALIBRATION_STATE`가 인메모리**라 프로세스 재기동 시 10분 rate-limit이 초기화된다.
  guiserver와 CLI가 각자 별도 상태로 같은 `yok3x.json`을 쓴다.
- 사용자 설정은 현재 `autocalibrate: false`다. 이 수정을 적용해도 **자동으로 켜지지 않는다** —
  켜는 것은 설정 변경이라 사용자 판단으로 남긴다.

## 교훈

측정값으로 파라미터를 역산할 땐 **분자와 분모가 같은 구간을 재는지부터 확인하라.**
창 정의가 다르면(롤링 vs 텀블링) 오차가 노이즈가 아니라 **창 주기에 위상 고정된 계통 편향**이
되고, 이런 편향은 스텝 제한·클램프 같은 시간영역 감쇠로는 절대 제거되지 않는다.
BUG-35처럼 "튀니까 변화량을 제한하자"는 대응은 증상을 느리게 만들 뿐 원인을 못 건드린다 —
진동이 **주기적**이면 노이즈가 아니라 모델 오류를 의심해야 한다. 관련: [[BUG-33]], [[BUG-37]].
