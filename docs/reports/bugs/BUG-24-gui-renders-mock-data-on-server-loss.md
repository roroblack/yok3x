# BUG-24 — 서버 연결이 끊기면 GUI가 **가짜 사용량**을 진짜처럼 표시

- 발견: 2026-07-20, 사용자 보고("그냥 서버 연결이 끊어진 상태임. 그래서 클라가 안열리는 거였음")
- 심각도: **높음** — 잘못된 쿼터 판단을 유도할 수 있음
- 상태: 수정 완료

## 증상
서버(`yok3x gui`)가 죽은 뒤에도 페이지가 정상처럼 보인다. 사용량 그래프에 그럴듯한 숫자가
떠 있고(claude 31% · codex 24% 등), 화면 어디에도 "연결이 끊겼다"는 표시가 없다.
사용자는 남은 쿼터가 넉넉하다고 **오판할 수 있다**.

## 근본 원인
`load()`의 실패 경로가 **두 가지 상황을 구분하지 않았다.**

```js
catch(e){setLive(false);render(MOCK);}   // 수정 전
```

- (A) 처음부터 서버 없음(html 파일 직접 열기) → mock 시연 모드. **정상 동작**
- (B) 쓰던 중 서버가 죽음 → **사고인데 (A)와 똑같이 처리**

(B)에서 `render(MOCK)`이 실행되면서 `MOCK` 상수의 **데모용 사용량 수치가 실데이터를 덮어썼다.**
배지 문구도 `○ MOCK(파일 직접 열림)`이라 (B)에서는 **오진을 유도**한다 — 파일을 직접 연 적이
없는데 그렇게 말한다.

부수적으로 다른 fetch 실패들도 전부 `catch(e){}` 빈 블록이라 실패 사실이 아무 데도 안 남는다.

## 수정
`gui/index.html`
1. `everLive`(한 번이라도 실데이터 수신) · `fails`(연속 실패 횟수) 상태 추가.
2. (B)에서는 **`render()`를 호출하지 않는다** — 마지막 실데이터를 그대로 유지. MOCK으로 덮지 않는다.
3. 상단에 `서버 연결 끊김` 배너 표시 + 연속 실패 횟수/경과 시간 안내.
4. 배지·출처 문구를 상황별로 분기: `○ 연결 끊김(갱신 중단)` vs 기존 `○ MOCK(파일 직접 열림)`.
5. 재연결되면 배너 숨김 + `fails=0` 리셋.

## 검증 (실제 브라우저)
| 단계 | 결과 |
|---|---|
| 서버 정상 | `● LIVE` · 배너 `none` · `everLive=true` |
| 서버 종료 후 ~49초 | 배지 `○ 연결 끊김(갱신 중단)` · 배너 `block` · "연속 7회, 약 49초" |
| 같은 시점 데이터 | **`mockLeaked: false`** — 버전이 실제 `v3.6.0` 유지(`3.0(mock)`으로 안 바뀜) |
| 차이 나는 부분 | 배지·시계·배너뿐. 사용량 수치 그대로 |
| 서버 복구 후 | `● LIVE` · 배너 사라짐 · `fails=0` |

`216 passed` (회귀 없음).

## 남은 것(별건)
다른 fetch 호출들의 빈 `catch(e){}`는 그대로다. 설정 저장 실패 등이 조용히 묻힌다 — 별도 판단 필요.
