# BUG-20 · 실시간 사용량 스트립: 창별 색상 오류 + 7d 예산 눈금 누락

- **상태**: 수정 완료 (2026-07-16)
- **심각도**: 중간(오해 유발 — 여유 있는 창까지 경고색) + 기능 누락
- **영역**: `gui/index.html` — 콘솔 실시간 사용량 스트립(`c-usage`) 렌더

## 증상
1. claude의 **5h가 노란색(warn)이 되면 7d(64%)·7d·Fable(13%)까지 전부 노란색**으로 변함.
   실제로는 7d·Fable은 한참 여유가 있는데도 경고색이라 오해를 유발.
2. **하루 페이싱 주간 예산(14%) 눈금이 7d 그래프 바에 표시 안 됨**. (대시보드에만 넣었고 콘솔
   스트립엔 없었으며, 페이싱 off면 아예 안 그려졌음.)

## 근본 원인
1. 스트립이 각 창의 색상 클래스를 **툴 전체 레벨(`t.level`)**로 칠함:
   `class="us-win ${t.level==='warn'?'warn':''}"`. 5h가 warn이면 `t.level='warn'`이라 **모든 창**이 warn.
   창은 자기 `used_percent` 기준으로 칠해야 함(대시보드 게이지는 이미 창별 `fclsPct`를 씀).
2. 콘솔 스트립 렌더에 pace/예산 눈금 호출이 없었음. 대시보드 눈금(`paceMarks`)은 `t.pace`(페이싱
   enabled+실측)일 때만 생겨서, 페이싱 off면 14% 기준선이 어디에도 안 보였음.

## 수정
1. **창별 색상**: `wlvl(used_percent, guard)` 헬퍼(창 자기 %로 stop/warn/'' 판정)로 교체.
2. **예산 눈금 항상 표시**: `budgetRuler(s, wname)` 추가 — 7d 창에만, `cap_pct`(주간의 하루치,
   기본 14%)의 **배수마다 세로 눈금**(14%=하루치[강조], 28·42…98%=일수 경계[점선]). 페이싱 on/off와
   무관하게 `cap_pct`가 있으면 항상. 콘솔 스트립 + 대시보드 7d 바 양쪽에 적용(대시보드는 페이싱
   enabled면 `paceMarks` 동적 띠, 아니면 `budgetRuler` 정적 눈금).

## 검증
- `wlvl`: 5h@83→warn, 7d@64→''(초록), Fable@13→''(초록), 99→stop.
- `budgetRuler('7d')`: 14(pcap)·28·42·56·70·84·98(pday) 7눈금. '7d·Fable'·'5h'는 빈 문자열.
- 실제 DOM 렌더(합성 실측 주입): 5h=warn / 7d=green+눈금7 / Fable=green. 90 passed.
