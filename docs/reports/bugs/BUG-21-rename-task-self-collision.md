# BUG-21 · 작업 이름 수정: 같은 이름으로 바꾸면 "이미 있다"로 실패

- **상태**: 수정 완료 (2026-07-17)
- **심각도**: 중간(정상 조작이 막힘 — 사용자 보고)
- **영역**: `yok3x/guiserver.py` — `_rename_task`

## 증상
`✏️ 이름 수정`에서 **이름을 바꾸지 않고 그대로 확인**하거나 같은 이름을 입력하면:
```
이름 수정 실패: 같은 이름의 작업이 이미 있다
```
프롬프트가 **현재 이름을 미리 채워주므로** 사용자가 가장 흔히 밟는 경로다.

## 근본 원인
```python
new_path = _task_path(cfg, new_name)
if new_path.exists():                      # ← 자기 자신인 경우를 제외하지 않음
    return {"error": "같은 이름의 작업이 이미 있다"}
```
새 slug가 기존 slug와 같으면 `new_path == old_path`인데, 그 파일은 **당연히 존재**하므로
자기 자신과의 충돌로 오판해 거부했다.

## 수정
`same_file = new_path == old_path`를 두어:
- **자기 자신이면 충돌 아님** → 파일 이동 없이 `label`만 갱신하고 원본 삭제를 건너뛴다
  (`"My Task"` → `"my task"`처럼 표시만 바꾸는 정상 케이스도 지원).
- **다른 작업과의 진짜 충돌은 그대로 거부**(원본·충돌대상 모두 보존).

## 검증
- 같은 이름 rename → ok, 파일 보존, 내용(목표·workdir) 보존.
- 다른 작업 이름으로 rename → 여전히 거부, 원본·충돌대상 둘 다 보존(회귀 없음).
- 정상 rename(새 이름) → 새 파일 생성 + 옛 파일 삭제.
- 회귀 테스트 `test_rename_task_same_name_updates_label_in_place` 추가. **153 passed**.
