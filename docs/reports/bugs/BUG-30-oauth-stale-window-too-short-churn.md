# BUG-30 · OAuth stale 창(15분)이 짧아 실측↔추정이 자주 깜빡임

- **상태**: 수정 완료 (2026-07-22)
- **심각도**: 낮음~중간(표시 신뢰성 — 사용자 지적 "왜 또 이래?" 반복 재현)
- **영역**: `yok3x/config.py`·live `yok3x.json` — claude `limits.max_stale_sec`

## 증상

A+B(OAuth 재활성, BUG-27 후속) 도입 후 claude 사용량 배지가 `실측`(OAuth, 정확) ↔ `추정`(트랜스크립트,
5h 롤링 과대집계) 사이를 자주 오갔다. 사용자가 같은 화면을 여러 번 다시 보고할 만큼 체감 churn이 컸다.

## 근본 원인

OAuth usage 엔드포인트는 간헐적 429 버그(claude-code #31637)를 가진다. `_probe_claude_oauth`의
stale-while-error 창(`max_stale_sec`)이 기존 900초(15분)로 짧아, 429가 15분 넘게 지속되면(흔함) 곧바로
추정(트랜스크립트 롤링, 5h는 리셋경계 무시라 과대표시)으로 떨어졌다. 게다가 이 세션에서 GUI 서버를
여러 번 재시작해 in-memory OAuth 캐시(`_OAUTH_LIVE_CACHE`)가 매번 초기화된 것도 churn을 가중했다.

## 수정

`max_stale_sec` 900 → **3600(1시간)**으로 확장(config.py 기본값·live 모두). OAuth가 잠깐 429여도 마지막
실측을 1시간 유지하며 `(⚠N분 전 실측)`으로 정직 표시 — 값을 지어내지 않으면서 깜빡임만 줄인다.

## 검증

- 실측 배지에 `(⚠N분 전 실측·백오프 중)` 정직 표시 확인.
- 근본 한계(OAuth 간헐성 자체)는 코드로 못 없앰 — Anthropic 엔드포인트 버그. 정직하게 안내.

## 교훈

간헐적으로 실패하는 외부 소스에 의존할 때는 **stale 유지 창을 그 소스의 실패 지속시간 분포에 맞춰
넉넉히** 잡아야 표시가 안정된다(1시간 vs 15분). 개발 중 반복 프로세스 재시작도 캐시 기반 안정성을
흔드는 요인임을 인지해야 한다. 관련: [[BUG-27]](A+B OAuth), [[BUG-29]](페이싱 소스 정렬).
