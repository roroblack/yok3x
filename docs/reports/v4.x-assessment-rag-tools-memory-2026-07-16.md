# v4.x · 평가 — RAG · 워커 도구(TOOL) · 장단기 메모리, yok3x에 도입할 가치가 있나 · 2026-07-16

사용자 질문("별도 RAG 쓸만하지 않나?", "TOOL·장기/단기 메모리는?")에 대한 아키텍처 판단.
공통 결론: **셋 다 이미 yok3x에 의존성 0 형태로 있거나 로드맵에 있음. 남의 프레임워크 통째 도입은 원칙
위배·과설계.** "왜 안 쓰지?"가 아니라 "능동 조사 + 의존성 0 + 수동 승급으로 대체했다"가 일관된 답.

## 1. 별도(벡터/임베딩) RAG — 판정: **미채택(지금은)**
### 이미 있는 것
- `knot.query()` = **의존성 0 RAG-lite**: 저수준(키워드×최신성) + 고수준([[링크]]·태그 확장) 이중레벨
  + consolidation(요점추출·중복제거·최신성 감쇠). 코드 주석: "임베딩 없이 그래프/텍스트만".
- ADOPTIONS: **LightRAG·Mem0 프레임워크(벡터DB) 명시적 기각**("의존성 0 위배·과설계"), 아이디어만 이식.
### 왜 별도 벡터 RAG가 값 안 하나
1. **의존성 0 정면 위배**: 임베딩 모델 + 벡터 저장소 = 프레임워크(chroma/faiss) 또는 API(임베딩 엔드포인트).
2. **코드 이해엔 RAG가 틀린 도구 — ACQUIRE가 증명**: "이슈 임베딩→유사 청크"(수동 RAG)는 "에이전트가
   셸로 능동 탐색→근거 QA"(ACQUIRE)보다 열등(논문 핵심). 워커는 이미 grep/read로 저장소 직접 접근.
   청크 임베딩은 청킹 경계·최신성·"의미는 비슷한데 틀린" 실패모드만 추가.
3. **노트(knot)는 작고 구조화됨**: 링크로 엮인 큐레이션 마크다운. 임베딩 recall 우위는 크고 비구조적
   코퍼스에서 나옴 — 여기는 키워드+링크 확장으로 충분.
### 값을 할 지점(공정하게)
- knot이 수천 다세션 노트로 커지고 키워드/링크 recall이 **실측으로** 무너지면 → 의미검색 계층 고려.
- 큰 **외부 코퍼스**(라이브러리 문서·RFC·스펙 = ACQUIRE "Ecosystem & Standards" 축).
- 그때도 yok3x답게: opt-in + 백엔드 임베딩 엔드포인트 재사용 or stdlib BM25, **벡터DB 프레임워크 금지**.

## 2. TOOL(워커 도구) — 판정: **가치 있음, 이미 로드맵(안전 봉투 안에서)**
- **현 상태**: 워커 CLI(claude/codex/gemini)는 이미 bash·read·grep·edit 보유. yok3x가 `--disallowedTools`로
  **기본 차단(텍스트 생산자=안전)**한 것뿐.
- **확장 = MCP 후보**(`v4.1.0-plan-mcp-worker-tools`): file/git/db/web 도구를 opt-in·화이트리스트·승인게이트·
  감사로그·읽기전용 기본·fail-closed로. 보류 이유는 "텍스트=안전" 완화라 신중해야 해서(가치 없어서 아님).
- **ACQUIRE 직결**: Answerer는 "읽기전용 조사" → **호출별 read-only 프로필**(codex `--sandbox read-only`,
  gemini `--approval-mode plan`, claude 읽기도구만)이 필요. 도구 사용의 가장 안전한 첫 조각, MCP 전체보다 선행.

## 3. 장기 & 단기 메모리 — 판정: **이미 2계층 존재. 핵심 자산은 "분리 + 수동 승급"**
| 계층 | yok3x 구현 | 출처 |
|------|------|------|
| **장기(persistent)** | **knot** — 지식그물 + consolidation + 이중레벨 검색 | Mem0/LightRAG 이식 |
| **단기(working)** | 런별 상태(`.yok3x/runs/<id>/`·프롬프트·escalate·pace) + **ACQUIRE QA**(이슈별 일시) | ACQUIRE |
- **핵심 원칙(피 흘려 배움)**: 단기를 장기에 섞지 마라. ACQUIRE QA를 knot에 저장 금지 = **BUG-13 자기오염
  루프**(런 산출물 재주입) 재발 방지. codex 심사도 못박음.
- **승급(promotion)**: 자동 금지. 재사용 가치 검증된 사실만 **사용자가 commit SHA·출처와 함께 수동 승급**.
  Mem0/Letta류의 자동 요약·승급이 바로 자기오염의 원천 → yok3x는 의도적으로 수동·큐레이션.
- **피할 것**: 메모리 프레임워크(Letta/MemGPT·Mem0·Zep) 통째 도입, 벡터 저장소 장기기억, 자동 승급.

## 종합 결론
- 셋 다 **의존성 0 + 안전게이트 + 능동 조사 + 수동 승급**으로 이미 구현했거나 로드맵에 있음.
- **다음 실전 작업 = ACQUIRE S2**(오케스트레이터 연동)가 이 세 조각 — 단기 메모리(QA) · read-only 도구 ·
  능동 조사 — 를 한 번에 검증하는 지점. RAG/메모리 프레임워크 도입보다 우선.
- 재검토 트리거: knot recall이 규모에서 **실측으로** 무너질 때만(그때도 프레임워크 없이 opt-in).
