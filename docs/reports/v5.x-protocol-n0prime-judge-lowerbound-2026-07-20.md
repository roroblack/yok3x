# v5.x · 사전등록 프로토콜 — N0′ 심판 **변별 smoke test** · 2026-07-20 (**v2 개정**)

**v1 → v2 개정 사유(중요).** v1 프로토콜과 v1 생성기에 방법론 결함이 있었다. 사용자가 결과를 의심했고,
codex 비평으로 확인됐다. **개정 시점에 심판 채점은 단 1회도 실행되지 않았다** — 결과를 본 뒤 기준을
옮긴 것이 아니므로 p-hacking이 아니다. v1 기록은 아래 "폐기된 v1"에 남긴다.

## 이름 정정 — "하한 검사" ✗ → **"변별 smoke test"** ○
codex 지적: 합성 변이는 실제 결함보다 **쉬울 수** 있다. 따라서
- **실패 = 강한 부정 증거**(명백한 결함조차 못 잡는 심판) → 자동화 금지 확정
- **통과 = 실전 성능의 하한 보장이 아님** — 낙관적 smoke test 통과일 뿐
"하한(lower bound)"은 통과 시 성능 바닥을 보장한다는 함의가 있어 부정확하다.

## 이 실험이 답할 수 있는 질문 (범위 고정)
> 이 코드베이스·이 연산자 집합·이 컨텍스트·이 모델 버전에서, 심판이
> **유효하고 테스트로 확인된 단일 합성 변이**보다 **원본 코드**를 더 높게 평가하는가?

**답할 수 없는 것(주장 금지)**: 테스트가 실제 결함의 몇 %를 놓치는가 · 심판이 LLM의 실제 결함을 몇 %
탐지하는가 · SCORE가 확률적으로 calibration 되었는가 · 타 저장소/모델/프롬프트 일반화 ·
심판을 자동 게이트로 써도 안전한가.

## 하지 말 것 (scope guard)
- 결과를 **실전 성능 증명으로 확대 해석 금지**(합성 변이 ≠ LLM 실제 결함).
- **같은 표본에서 심판 프롬프트 튜닝 후 재시험 금지.**
- mutation framework 도입 · 전체 mutation coverage · 20쌍 초과 확장 **금지**.
- **변이가 살아남도록 테스트 수정 금지.**
- 제품 코드에 실험 코드 투입 금지.
- **생존(SURV) 변이로 "테스트 커버리지/결함 누락률"을 주장하지 않는다** — 등록된 분석 범위 밖이다.

## 중단 조건
- 한 세션 내 유효 kill 20개 확보 실패 → 중단.
- 한 연산자가 표본 절반 초과 → 대표성 부족으로 중단.
- baseline 불안정(2회 연속 통과 실패) → 중단.
- 블라인드 누출·실행 조건 차이 발견 → 해당 실행 폐기.
- **미달 시 "튜닝해서 통과" 금지. 심판 의존 로드맵(F·D·T4·N1~N3) 동결.**

## 비용
변이 생성·라벨링 **$0**. 심판 채점 **40호출**(정상 20 + 변이 20 각각 독립 채점).
v1의 "20호출"은 오산 — 절대 채점 방식에서 paired 분석을 하려면 양쪽 다 채점해야 한다.
