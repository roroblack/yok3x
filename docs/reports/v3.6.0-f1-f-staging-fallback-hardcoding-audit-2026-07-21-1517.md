# v3.6.0 · F1-f 스테이징 폴백·하드코딩 감사 · 2026-07-21 15:17

RULE §5.5에 따라 F1-f가 추가한 폴백과 안전 상한을 기록한다.

| 위치 | 항목 | 필요한 이유 | 표시/설정 |
|---|---|---|---|
| `Orchestrator._run_round_verify` | 스테이징 준비 실패 → 원본 verify | 후보 준비 문제로 전체 런이 중단되는 것을 막고 기존 동작으로 안전하게 열화 | `[verify-stage] ... 스테이징 실패 ... 원본 verify 폴백` 로그와 `verify_scope=original_tree` |
| 같은 함수 | workdir 파일수 상한 초과 → 원본 verify | 매 라운드 무한·과대 복사를 방지 | 복사 전 파일수/바이트와 초과 로그. task `changes.stage_max_files`로 조정(기본 5000) |
| `STAGE_IGNORED_NAMES` | `.git`, `node_modules`, `.yok3x`, `yok3x-out`, `__pycache__`, `.tmp`, `*.pyc` 제외 | VCS·의존성·런 산출물·캐시의 재귀/과대 복사와 오염 방지 | 프로토콜성 안전 제외 목록이며 매 라운드 scan 로그로 복사 규모 노출 |

기본 5000은 사용자 환경값을 고정한 것이 아니라 설정으로 재정의 가능한 폭주 방지 기본 상한이다. 폴백 관측은
candidate 라벨로 가장하지 않고 `original_tree`로 기록되므로 캘리브레이션에서 fail-closed로 제외된다.
