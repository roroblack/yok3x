## 1. 사전등록 판정 — **통과**
| 지표 | 값 |
|---|---|
| win / tie / loss | **17 / 2 / 1** |
| paired sign test (tie 제외 n=18) | **p = 0.00014** |
| 사전등록 판정선 | win ≥ 15/20 **AND** p < 0.05 |
| **결과** | **통과** |

point-biserial **0.644**(보조지표 — 상관이지 calibration 아님).
정상 평균 **4.80**(범위 3~7) · 변이 평균 **2.80**(범위 0~5).

→ 심판은 **명백한 합성 결함을 원본보다 낮게 평가한다.** "심판이 완전한 연극"이라는 가설은 기각됐다.

## 2. 더 중요한 발견 — **제품 게이트 임계 8.0이 모든 코드를 탈락시킨다**
사전 고정 cutoff **8.0**(제품 기본값 `cli.py --threshold 8.0`)로 혼동행렬을 그리면:

| | 예측 통과(≥8) | 예측 차단(<8) |
|---|---|---|
| **정상 코드**(20) | TP **0** | FN **20** |
| **변이 코드**(20) | FP **0** | TN **20** |

- **정상 코드가 게이트를 통과한 비율: 0%** — 우리 정상 코드 SCORE 최고값이 **7.0**이다.
- 변이 차단률은 100%지만, **아무것도 통과시키지 않으므로 의미 없는 100%**다.

즉 **심판에는 신호가 있는데(상관 0.644) 게이트 임계가 척도와 어긋나 있다.** 현재 설정으로
producer-reviewer를 돌리면 심판은 **정답 코드조차 계속 반려**하고, 라운드는 escalate/stall로 흘러
토큰만 태운다. 이건 "심판이 나쁘다"가 아니라 **"임계가 틀렸다"** 는 별개의 결함이다.

참고(사후 계산이므로 판정 근거 아님): t=4에서 분리 정확도 82%, confusion@4.0은
precision 0.76 · recall 0.95. **이 값을 그대로 새 기본값으로 채택하지 말 것** — 사후 선택 편향이며,
임계 재설정은 별도의 사전등록 실험이 필요하다.

## 3. 심판이 약한 결함 유형
| 연산자 | 승률 |
|---|---|
| return_sub (`return X`→`None`) | **5/5** |
| comparison (비교 뒤집기) | **4/4** |
| guard_off (`if X:`→`if False:`) | 4/5 |
| logic (and↔or) | 1/1 |
| **boundary (정수 리터럴 ±1)** | **3/5** ← 가장 약함 |

**off-by-one류를 가장 못 잡는다.** 유일한 LOSS(쌍 0, Δ=-1.0)도 여기서 나왔다. 표본이 작아
(연산자당 1~5개) 확정적 결론은 아니지만, 방향은 직관과 일치한다 — 경계값 결함은 문맥 없이
함수만 봐서는 판별하기 어렵다.

## 4. 이 결과로 주장할 수 있는 것 / 없는 것
**주장 가능**: 이 코드베이스·이 연산자 집합·이 컨텍스트·`gpt-5.6-sol xhigh`에서
심판은 테스트로 확인된 단일 합성 변이보다 원본을 유의하게 높게 평가한다.

**주장 불가**(프로토콜 §범위 고정 그대로):
- 테스트가 실제 결함의 몇 %를 놓치는가
- 심판이 **LLM이 실제로 만드는 결함**을 몇 % 탐지하는가 — 합성 변이는 실제 결함보다 **쉬울 수 있다**
- SCORE가 확률적으로 calibration 되었는가 (0.644는 상관일 뿐)
- 타 저장소·모델·프롬프트로 일반화
- **심판을 자동 게이트로 써도 안전한가** — 특히 §2를 보면 현재 설정으로는 **안전하지 않다**

**잔존 편향**(v2도 제거 못함): killable만 선택 → 테스트가 잘 덮는 영역·즉시 크래시 편중(spectrum bias).

## 5. 로드맵 판단
- **F·D·T4·N1~N3 동결 해제 조건 중 "심판에 신호가 있는가"는 충족.** 단 아래 선행 과제가 있다.
- **선행 과제(신규·최우선): 게이트 임계 재설정.** 현재 8.0은 전량 반려다. 사후 최적값(4)을 그냥
  쓰지 말고, **별도 사전등록 + 실제 런 데이터(F0 `calibration.jsonl`)로 검증**해야 한다.
  이건 §2가 드러낸 **실전 결함**이므로 나이틀리보다 우선한다.
- N1(섀도 나이틀리)은 임계 재설정 이후로.

## 6. 부수 발견
- `calibration.make_record(**kw)`는 **모르는 키를 조용히 버린다.** 내가 `verify_passed=`로 잘못 부르자
  오류 없이 `verify_ok=None`이 되어 상관이 `None`으로 나왔다. 오타 하나가 침묵 실패가 된다.
  → 알 수 없는 키를 거부하거나 경고하도록 고칠 후보(별건).
- 실험 스크립트는 제품에 넣지 않았다(scope guard 준수). 산출물: `mutants2.jsonl`·`scores.jsonl`.
