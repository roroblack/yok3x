- **주의(반대 근거)**: 회복 44 vs 회귀 22(순증 +22, 회복 2당 회귀 1). Python·단일 벤치만 검증.

## 우리 상황에 맞춘 설계 결정 (codex 조사 반영)
1. **새 최상위 패턴 아님 → 기존 패턴 앞 preflight 단계**. task spec에 `acquire:{...}` 옵션으로 얹는다
   (ARIS 적대적리뷰를 옵션으로 얹은 방식과 동일). Resolver = 기존 producer-reviewer/pipeline/fanout.
2. **QA는 knot에 저장 금지**. `.yok3x/runs/<run_id>/acquire.json`(이슈별 일시 작업메모리·감사용)에만.
   → **BUG-13 자기오염 루프**(자동 산출물 재주입) 재발 방지. 논문의 "이슈별 일시 메모리"와도 일치.
   재사용 가치가 확인된 사실만 사용자가 commit SHA·출처와 함께 knot으로 **수동 승격**.
3. **호출별 read-only 프로필** 필요: codex `--sandbox read-only`, gemini `--approval-mode plan`,
   claude=읽기 도구만 허용하는 명령 프로필. Answerer는 코드 수정 불가.
4. **비용 게이팅(opt-in)**: 단순수정·신규생성은 생략, 낯선 저장소·원인불명 다중모듈만 QA 2개.
   가드 warn=QA 1개, hard stop/headroom 부족=선행 단계 생략. 페이싱·승인 게이트 연동.
5. **QA 스키마 강화(사용자 제안 반영, codex 평가)**:
   - `evidence`[{path,symbol,observation}] **강제**(행번호보다 symbol 우선 — 세부오류 대부분이 행번호).
   - `unknowns` **강제**(증거부족을 답으로 인정). `confidence`=참고만(게이트로 쓰지 않음).
   - `alternative_hypotheses`=필드는 두되 **빈 배열 허용**(매번 대안 지어내면 오가설만 증가).
6. **Resolver 수정 전 재검증**: 별도 LLM 호출 없이 Resolver **첫 도구 행동**으로 QA마다 핵심 주장
   하나를 직접 열어 `confirmed/partial/contradicted` 기록. contradicted=폐기, partial=위치힌트로만.
   (오고정 5건엔 직접 유효. 과일반화 17건은 수정범위검토+테스트+적대적리뷰로 별도 대응.)

## 단계별 진행 (각 단계: codex 구현 → Claude 검토 → 커밋 → HISTORY)
- **S0 (이 문서)**: assessment+plan 문서화 + ADOPTIONS '이식 후보'에 ACQUIRE 추가. **[Claude]**
- **S1 — `acquire.py` 순수 모듈**: **[codex 구현]**
  - Questioner 프롬프트 빌더(질문 정확히 2개, 4범주, **해결책·패치·수정위치 제안 금지**).
  - Answerer 프롬프트 빌더(읽기전용·근거필수·모르면 '모른다'·다른 QA 미주입).
  - QA JSON 스키마 검증(위 5항: evidence 강제/unknowns 강제/confidence 참고/alt 빈배열 허용).
  - QA→Resolver 컨텍스트 블록 렌더(상한). 순수 함수(부작용·네트워크 없음) → 단위테스트 용이.
  - `tests/`: 질문 2개·중복금지·수정안 금지, 스키마 거부/통과, 렌더 상한, 근거없음 처리.
- **S2 — 오케스트레이터 연동**: **[codex 구현]**
  - `run_acquire_preflight()`(Questioner→Answerer들, MVP는 순차 OK), read-only 호출 변형.
  - `run_task_file`에서 `spec.get("acquire")` 시 선행 실행, QA를 첫 build 단계 `extra_context`로 선주입.
  - `.yok3x/runs/<run_id>/acquire.json` 저장(knot 저장 안 함). 비용 게이팅·승인 배치.
- **S3 — 강화**: **[codex 구현]** Resolver 재검증(첫 도구 행동), 진짜 병렬 `call_workers_parallel()`
  (단계번호·승인·비용 원자적 선예약, 로그/usage 동기화) — fanout에도 재사용.
- **S4 — 파일럿 A/B**: 대표 이슈로 기존 경로 vs ACQUIRE. 성공률+기존성공→실패+비용+시간+변경파일수 측정.
